# WEXUM Motion System — фирменный язык движения

> **Статус: PROPOSED / для рассмотрения основателем, CTO, UX и Accessibility.** Это дизайн-спецификация, а не подтверждение реализации в клиентах.  
> **Область:** WEXUM (все самостоятельные продукты и Wexum Hub), приоритетный пример — WexumVPN.  
> **Связь:** [WEXUM Brand Guidelines](../WEXUM_BRAND_GUIDELINES.md), [VPN product epic #12](https://github.com/Dimash313/Wexum/issues/12), платформенные направления Android #5, iOS #6, Desktop #7.  
> **Ответственность:** общие дизайн-правила обсуждает CTO; платформенные команды адаптируют реализацию на своих платформах. Никаких правок нативных клиентов или общих API этим документом не проводится.

## 1. Суть фирменного движения

**Precision in motion.** WEXUM узнаётся по тому, что элементы будто выточены из одной геометрической системы: точная ось, сдержанный импульс, мгновенная ясность статуса. Уникальность создаётся **последовательностью и ритмом**, а не декоративной сложностью.

Пять неизменных принципов:

1. **Geometric:** движение по прямым и диагональным осям, согласованным с углами знака W; никогда не деформировать утверждённый логотип.
2. **Intentional:** каждое движение объясняет действие, навигацию или состояние, либо даёт едва заметную атмосферу на главной поверхности.
3. **Quiet power:** контраст, лаконичная геометрия и ограниченный световой акцент; не использовать цветные неоновые вспышки, партиклы, вращающийся логотип, скруглённую «желеобразную» пластику.
4. **Honest:** анимация не может изображать успешное VPN-подключение до подтверждённого системой защищённого состояния.
5. **Accessible & efficient:** снижение движения, отсутствие вспышек, остановка фоновой анимации вне видимого экрана и экономное потребление энергии.

## 2. Фирменные движения (motion primitives)

### W-Trace — геометрический штрих

Короткая линия появляется вдоль диагональной грани панели или подчеркивает выбранную вкладку. Направление задаётся геометрией логотипа; **логотип не анимируется и не перерисовывается**. Продолжительность 260–420 мс. Стандартная функция: ease-out. Линия не должна бегать по всей странице или повторяться бесконечно.

**Использовать:** появление hero-секции, выбор продукта, акцент на первом входе. **Не использовать:** на каждом нажатии, вводе символа или прокрутке.

### Precision Shift — переход между поверхностями

Исходная поверхность за 90–140 мс уходит по opacity; новый экран входит на 8–16 px вдоль направления навигации и становится полностью виден за 200–260 мс. Общая длительность обычно 240–320 мс, с перекрытием фаз, без пустого кадра.

**Использовать:** переходы между разделами, списком серверов и подробностями, настройками и профилем. Для обратной навигации — противоположная семантическая ось. Уважать RTL, если направление связано с reading order.

### Lock Pulse — подтверждение результата

**Однократный** монохромный импульс по контуру центрального элемента после проверенного успешного завершения действия. Максимум 360–480 мс; затем фиксированный стабильный вид. Никакого бесконечного ослепляющего сияния.

**Использовать:** подтверждённое защищённое VPN-соединение; в других продуктах — только для действительно завершённого действия, не для запуска фоновой операции.

### Panel Reveal — раскрытие структур

Группы карточек входят единым движением с отставанием 25–40 мс между соседними элементами, максимум три ступени; общая композиция полностью готова не позднее 420 мс. Сдвиг не более 12 px; не анимировать десятки элементов последовательно.

**Использовать:** открытие подборок продуктов, серверов, настроек. Для длинных списков — статическая виртуализация без каскадной анимации каждого ряда.

### Ambient Edge — спокойная жизнь главного экрана

Практически статичный атмосферный слой из двух–трёх тонких линий/граней, расположенных вне текстовых блоков. Низкая интенсивность: opacity примерно 0.06–0.12 на тёмном фоне; плавный цикл 10–14 секунд без скачка положения, без изменения логотипа. Движение может ограничиваться одним лёгким изменением яркости или коротким проходом контура. Для светлой темы — симметрично низкоконтрастные графитовые линии.

**Использовать:** исключительно главная/hero-поверхность, splash при необходимости. **Отключать:** при фоновой работе, при экономии энергии, в списках, на экранах ошибок и при Reduce Motion.

## 3. Тайминги и динамика (проектируемые дизайн-токены)

| Token | Продолжительность | Когда применять |
| --- | ---: | --- |
| motion.instant | 90 мс | Микроотклик |
| motion.fast | 160 мс | Нажатия, наведение, переключатели |
| motion.base | 240 мс | Стандартная смена поверхностей |
| motion.emphasis | 360 мс | Выразительное раскрытие |
| motion.hero | 480 мс | Однократный вход в главный экран |
| motion.ambient | 10–14 с | Очень слабый атмосферный цикл |

**Кривые:**

- Enter: cubic-bezier(0.22, 1, 0.36, 1) — уверенное быстрое появление и мягкая остановка.
- Exit: cubic-bezier(0.4, 0, 1, 1) — короткий сдержанный уход.
- Standard: cubic-bezier(0.2, 0, 0, 1) — функциональные изменения.
- Для истинно непрерывного слабого атмосферного слоя: ease-in-out.

**Границы:** смещение до 16 px (обычно 8–12), scale 0.98–1.00, rotation отсутствует для UI-компонентов, overshoot/bounce запрещены. Световые контуры допускаются лишь на нейтральных монохромных элементах; чистые #000/#FFF знака остаются неизменными.

Эти токены — **рекомендации на ревью**, не опубликованные контракты платформ и не обещание точного единого рендеринга на Android/iOS/Desktop.

## 4. WexumVPN: поведение главного экрана по состояниям

### Idle / disconnected

- Экран открывается одним W-Trace в зоне декоративной грани и спокойным Panel Reveal верхних информационных блоков; основной power-контрол **сразу видим и доступен**, без ожидания hero-анимации.
- Центральный контур кнопки статичный или с очень слабым Ambient Edge вдали от текста; никаких циклов, имитирующих сетевую активность.
- Статус «Не подключено» остаётся ясным. Нет вымышленных пинга, скорости, страны или «защиты».

### User taps connect / permission / connecting

- Нажатие: моментальный тактильный визуальный отклик 90–160 мс; разрешён лёгкий 1–2% shrink элемента, без подпрыгивания.
- Когда действительно инициирован процесс подключения, контур вокруг кнопки может показать **незавершённый** прогресс / штрих, пока состояние проверяется. Он никогда не заполняется до полного «защищено» по одному лишь времени анимации.
- Если требуется системное разрешение VPN, показывать явный статус «Требуется разрешение»; согласие пользователя само по себе **не означает защищённое соединение**.
- Длинное ожидание допускает неброский циклический индикатор внутри управляющего контура; всегда есть поясняющая текстовая метка, доступная скринридеру. Не вводить искусственную задержку ради красоты.

### Verified connected / protected

- **Только** после подтверждённого авторитетным VPN-движком состояния: один Lock Pulse по внешнему контуру 360–480 мс и затем спокойное заполненное кольцо.
- Обновить текст «Подключено / Защищено» и допустимую статистику только из проверенных источников. Нельзя использовать заглушки с выдуманными скоростями/пингом.
- Возможна краткая системная виброотдача, если пользователь не отключил её и платформа разрешает; звук и музыкальные сигналы **не требуются**.

### Disconnecting, disconnected, interrupted, failed, revoked

- Сначала немедленно отобразить реальное безопасное состояние, затем применить движение. Анимация **не должна задерживать** показ отключения/ошибки и не может продолжать белый сигнал «защищено» при потере достоверного подтверждения.
- Кольцо возвращается к нейтральному контуру за fast/base; без красного цвета, тревожного мигания или длинных декоративных эффектов.
- При прерванном подключении или отзыве полномочий отображать состояние без ложного protected. Поясняющий текст важнее анимации.

### Переключение сервера

- Открыть список через Precision Shift.
- Выделение выбранного сервера — однократный W-Trace или перемещение активного индикатора.
- При реальном переподключении следовать тем же правилам честного статуса; не показывать защищённое соединение на новом сервере до подтверждения.

## 5. Обязательный общий стандарт для продуктов

| Универсальное действие | Одинаковое поведение во всех WEXUM-продуктах |
| --- | --- |
| Открытие экрана | Precision Shift; одинаковый ритм и дистанция |
| Выбор пункта | Fast feedback; простой акцент без пульсации |
| Открытие карточки | Panel Reveal или короткий плавный expand |
| Подтверждение успеха | Один Lock Pulse только при настоящем успехе |
| Навигация назад | Обратная семантическая ось, без случайных смен направления |
| Главная поверхность продукта | Очень умеренный Ambient Edge, если поддерживает UX |
| Ошибка / потеря связи | Немедленная ясная смена состояния, затем минимум motion |

**Унификация — по правилам и токенам, а не по копированию одинакового шаблона каждого экрана.** WexumVPN может использовать кольцо подключения, продукт для файлов — контур завершения обработки, AI-продукт — Panel Reveal результата. Везде узнаётся одна динамика.

## 6. Нативные платформы, качество и безопасность

- **Android:** внедрять в собственном UI-модуле клиента, опираясь на поддержку Reduce Motion и accessibility settings Android; контрактные имена движений не должны подменять системные состояния VpnService.
- **iOS:** адаптировать длительности/кривые к SwiftUI/UIKit и системному Reduce Motion; respecter native swipe/back и VoiceOver, не ломать жизненный цикл NetworkExtension.
- **Desktop:** учитывать системные настройки reduced motion, фокус клавиатуры, мышь и разные refresh rates; UI-animation не имеет отношения к привилегированному сетевому процессу.
- **Web / Hub:** использовать transform и opacity там, где это возможно; не анимировать layout-heavy свойства при постоянном движении.

**Требования к приёмке:**

1. Состояние UI всегда отражает авторитетное состояние действия; тесты запрета ложного protected, в том числе disconnect/revocation/error, отмена permission, фон/возврат, устаревшие callback.
2. При включённой Reduce Motion исчезают Ambient Edge, диагональные перемещения и длительные эффекты; остаётся мгновенная смена статуса или короткая opacity без потери информации.
3. Не допускаются мерцания и резкие вспышки; все смыслы передаются также текстом, не только движением, цветом или вибрацией.
4. На целевых устройствах ставить ориентир 60 FPS для коротких переходов без регулярного jank; оценивать бюджет CPU/GPU/батареи на маломощных устройствах **реальными измерениями**, не выдумывать процент эффективности.
5. Не запускать фоновый цикл при свёрнутом приложении или невидимом экране; уважать энергосбережение.
6. Не копировать анимации/ассеты других VPN-продуктов; исходники лицензировать и проверять.
7. Тестировать мобильные и desktop-варианты, светлую/тёмную тему, RTL, локализацию, screen reader и динамический размер шрифта.

## 7. Порядок внедрения

1. Согласовать WEXUM Motion System с основателем/CTO как принцип бренда.
2. Создать **отдельный motion-prototype** главного экрана WexumVPN без изменения сетевого состояния; получить визуальное одобрение и проверить reduced-motion.
3. В каждом нативном направлении согласовать реализацию под его ограничения в собственном Draft PR, без обхода владельцев путей и общего CI.
4. Сначала закончить и проверить реальные VPN-state/engine контракты; привязать анимации к **verified** событиям, не к фиктивным таймерам.
5. После успешного UX/security/accessibility-review вынести общие **значения** токенов в платформенные адаптеры, не создавая скрытую зависимость между самостоятельными приложениями.

**Статус реализации на момент создания документа:** спецификация предлагается для ревью. Ни один нативный клиент не считается функциональным VPN из-за существования этого документа; реальные сборки и UX-анимации данным PR не проверялись.
