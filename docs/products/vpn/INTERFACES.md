## Rules shared by A–K

Consumers authenticate the producer and authorize the specific action, tenant and resource. Keep the **caller** (workload or user performing an operation), **subject** (affected account), **device**, **login session** and **tunnel session/attempt** distinct. A client may identify a desired resource but cannot supply authority over it. Each card identifies context that is intentionally absent. All service credentials and environments have separate audiences and purposes.

A mutation carries a stable opaque intent or event ID scoped to its authenticated producer, tenant and operation. Reuse with changed input returns `conflict`. A repeated request returns the original disposition only while it remains safe. It cannot revive revoked state or allocate a second session. Match authoritative revisions under concurrency. A deadline can expire after commit. Reconcile by the same ID before retrying. Read-only checks may repeat within their freshness limits. Adapters need underlying I/O deadlines and cancellation that actually stops work.

Proposed error classes are `invalid`, `unauthenticated`, `denied`, `stale`, `replayed`, `conflict`, `capacity`, `unavailable` and `unsupported_version`. Restrict externally visible detail where it could enumerate another owner. Distinguish denial from retryable transport faults in private metrics. Neither outcome grants access. Prefer bounded, versioned messages and additive opt-in fields. Unknown required security semantics, ambiguous fields or unsupported versions fail closed. Deploy verifying readers before new writers. Record only coarse error, operation and sanitized evidence identifiers. Retention and deletion require an owner-approved purpose per data class, including backups.

## F. Signed permit to node-side verifier · D2/D3/D4

- **Producer / consumer / owner.** Isolated signer issues. Native client transports the permit and proves possession over the authenticated connection. Assigned Gateway owner verifies against configured trust material, intended peer, live session authorization and control revisions. A bearer string alone cannot admit.
- **Proposed claims.** `{profile_version, issuer, kid, permit_ref, tenant_ref, subject_ref, device_ref, device_key_binding, login_session_binding, tunnel_attempt_binding, node_audience, registration_generation, scope, issued_at, not_before, expires_at, revocation_revision}`. Exact signed encoding, algorithm and key provider remain open. Verifier selects only the configured profile.
- **Freshness / concurrency / failure.** Check time, signature and peer proof locally, then hold a tentative slot for the deduplicated intent. The online authority orders its admission commit against revocation of the bound revisions. If revoke wins, reject. If admission wins, later revoke follows J. Reconcile an unknown commit before enabling forwarding, then finalize exactly one lease on the same peer and generation. Recheck local deny watermark before activating the engine. A late receipt cannot override a newer revoke. A duplicate authenticated query may learn the existing result. A different peer/session is denied. Replay/revocation state must survive restart or be recovered before admission. Unknown KID, timeout, clock anomaly and partition block new grants/admission.
- **Compatibility / privacy / acceptance.** Install verifier/profile readers before enabling issuer. No unsigned downgrade during mixed rollout.
