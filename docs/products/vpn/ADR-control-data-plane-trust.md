## Problem statement

Six independent prototypes can each accept a locally valid value while the system still lacks an authenticated end-to-end connection. The integration must establish who can enroll a device, which node can accept its session, what happens when that authority changes, and what measurements justify a protection claim.

## Goals and non-goals

Deliver contracts and falsifiable acceptance specifications for one native client, one isolated Gateway and synthetic accounts. Production billing, public APIs, deployment, a release verdict, multi-region scale and product implementation require separate owner work. This package contains no wire standard or operational guarantee.

## Constraints and trust boundaries

Identity owns verified subjects and sessions. Control owns tenant-scoped device state. Billing owns provider evidence. Entitlements owns eligibility. Registry owns inventory. Gateway owns actual capacity and admission. Clients own their OS boundary. Each service authenticates its caller and authorizes the exact operation. Hub is an optional scoped client. No cross-domain database reads. The packet worker receives only the session policy it needs. [Domain boundaries](https://github.com/Dimash313/Wexum/blob/ead392f9fd823814f35916823b0a477d571427c5/docs/architecture/BOUNDARIES.md) · [Threat model](https://github.com/Dimash313/Wexum/blob/7b97c64bb2459d60ede1ab03fe85011aaafe824c/docs/vpn/security/THREAT_MODEL.md)

## Decision proposal

1. **Control Plane.** Verify the login at a trusted Identity edge, resolve membership server-side and authorize every owner-scoped operation. Separate eligibility to enroll from eligibility to connect. Complete a device-key challenge before binding an active device. Record a revision on activation or revocation. A caller-supplied actor, device row or receipt cannot confer access.
2. **Management Plane.** Enroll the Gateway peer under a controlled trust root. Bind its current registration generation to that peer. Authenticate observation writers, authorize targets and reject stale generations. Distribute versioned configuration, revocations and public verifier material. Keep incident access and category-only metrics outside the packet process.
3. **Issue and admit.** Select a candidate node before naming its audience. An isolated signer rechecks current authority and binds tenant, subject, device key, session, node and generation. At each new admission or renewal, obtain fresh online authorization, validate the permit locally and atomically consume admission capacity and the attempt's replay state. Treat the authoritative admission commit as the ordering point against revoke. The Gateway can hold a tentative slot while it waits, but can only forward after it has the confirmed decision for that exact attempt. Revoke winning the race denies admission. Revoke after the commit follows J, even if the reply was lost. On an ambiguous reply, reconcile the original attempt. A partition or cache cannot establish new authority.
4. **Data Plane.** The authenticated Gateway verifies the peer proof, signature, scope, freshness, binding, revocation and replay state before enabling the reviewed engine. Identity and Billing stay outside the packet path. Reconnect requires a fresh admission. Handle existing sessions under a separately approved outage rule.
5. **Protection evidence.** Authenticate status from the privileged native adapter. Bind OS tunnel, engine session, attempt, generation, entitlement, device, current network path and routing/DNS evidence. Drop the UI protection claim on stale/conflicting evidence. Observe packet behavior independently to accept the lab slice. [Sequences](COMPONENTS.md) · [Boundary contracts](INTERFACES.md)

## Considered alternatives

| Choice | Recommendation for the lab | Benefit, cost and condition for revisiting |
|---|---|---|
| Single-process prototype or separate trust principals | Colocate ordinary control modules on one isolated host if helpful. Separate signer, management identity, Gateway and native privileges | Simplifies lab operations while limiting authority after compromise. Splitting every control module into a network service adds failure modes before there is load evidence. |
| Centralized introspection, wholly offline permits or hybrid admission | Fresh control decision at admission/renewal plus node-local signature and binding checks | Central-only increases dependence on the control service and leaves node identity/capacity checks necessary. Offline admission trades availability for stale authorization. Hybrid adds one admission round trip and a reconciliation obligation. |
| Signing key on nodes or isolated signing authority | Give nodes verifier material only | Limits minting power of a compromised node. Requires key distribution, acknowledgement, incident invalidation and a recovery drill. A compromised Gateway can still mishandle its own traffic. |
| Client first, backend simulator first or integrated vertical slice | Build trust and deny paths first, then one real engine and native client | A simulator can verify contracts cheaply but cannot validate OS routes. An early client-first demo has no trustworthy peer. Android has APK evidence. Desktop offers controllable Linux observation points but lacks privileged IPC and GUI CI. |
| Live payment or isolated fixture | Seek separate approval for a server-only synthetic lab authority | Avoids provider accounts, costs and personal data. Evidence applies only to synthetic eligibility. Production acceptance requires a real provider validation and reconciliation review. |

## Security and privacy tradeoffs

A short-lived capability limits exposure but duration alone cannot bind a device, prevent replay or communicate revocation. Online admission improves revocation observability but loses availability during partitions. Store the minimum transient admission state required for deduplication and incident cutoff. Separate this from product analytics. Never export tokens, secrets, destinations, queries, packet contents or payment data in ordinary logs. Lab path measurements use controlled synthetic endpoints and restricted, scrubbed evidence with an owner and deletion condition. [Key security](https://github.com/Dimash313/Wexum/blob/7b97c64bb2459d60ede1ab03fe85011aaafe824c/docs/vpn/security/ACCESS_AND_KEY_SECURITY.md) · [Privacy and operations](https://github.com/Dimash313/Wexum/blob/7b97c64bb2459d60ede1ab03fe85011aaafe824c/docs/vpn/security/PRIVACY_AND_OPERATIONS.md)

## Failure assumptions

Expect lost, duplicated, delayed and reordered messages, unavailable storage, clock faults, peer recreation and asymmetric partitions. A response can disappear after an operation committed. Preserve revocations across retry, restart and rollback. Unknown authority denies new connections. Existing-session behavior on lost control remains BLOCKED for approval. The UI can withdraw a claim without proving packets stopped. [Failure and privacy matrix](FAILURE_AND_PRIVACY_MATRIX.md)

## Operational and maintenance costs

| Owner | Recurring work and cost driver | Lab evidence before expanding |
|---|---|---|
| Identity / Backend | Session and membership reconciliation, device recovery, schema compatibility and storage repair | Revoke/restore drill, no cross-tenant reads, mixed-version test |
| Security / Operations | Signer custody, trust distribution, compromised-key response, epoch recovery and reconciliation lag | Observe acknowledgements or quarantine missing nodes. Demonstrate replay rejection after restart |
| Gateway / Clients | Engine updates, OS privileges, route cleanup, mobile transitions, test hardware | Reproducible engine/OS build, failure evidence and clean teardown |
| QA / Audit | Independent vantage points, sanitized artifacts, instrument calibration and deletion | Repeatable run manifest and negative controls on exact source |

## Compatibility and migration implications

Introduce internal adapters alongside the draft lane types. Old device rows require re-enrollment before key-bound access. Historical provider events require authenticated reconciliation before any eligibility promotion. Discard prior advisory selections on rollout. Deploy readers and rejection paths before issuers and native UI activation. Unknown security-critical semantics fail closed. Preserve event watermarks, deny state and key invalidations across rollback. [Impact and stage gates](LAB_MIGRATION_AND_ACCEPTANCE.md)

## Rejected shortcuts

Using PKCE success as login, exposing a constructor as authentication, treating a row as key ownership, signing any incoming candidate, admitting on a probe snapshot, accepting a client-paid flag, caching an OS-connected flag or accepting a classifier verdict as a leak measurement each skips a distinct authority. Unresolved review items stay with the affected source owner.

## Consequences and rollback

The first slice depends on synchronous authority at admission, one isolated verifier and a real OS observation rig. Losing any prerequisite can reduce availability. Before implementation, closing this docs PR withdraws the proposal. In the future lab, stop issuance and new admissions, invalidate lab roots and leases, stop the engine, verify route and DNS restoration and destroy synthetic state. A rollback must retain evidence of prior revocation until the environment is destroyed.
