# First isolated WexumVPN connection

**Proposed engineering and acceptance specifications · NOT RUN.** One synthetic native client must exchange controlled traffic through an authenticated Gateway. Acceptance requires reproducible evidence of approved DNS, IPv4 and IPv6 behavior. A successful build, handshake, OS icon or offline classification alone cannot satisfy this gate. [Decision register](ADR-control-data-plane-trust.md) · [Dependency graph](COMPONENTS.md) · [Failure matrix](FAILURE_AND_PRIVACY_MATRIX.md)

## Laboratory and first client

Use disposable local hosts or existing isolated equipment. Separate client underlay, Gateway egress, control/management and observers. Provide internal DNS and controlled IPv4/IPv6 endpoints. Restrict egress to the laboratory. Calibrate an independent forbidden-path observer by showing it can see a synthetic marker in an intentional baseline run. Exclude production, real users or keys, payment data, public IP-check services, paid servers and new external services. Any future ephemeral test material requires the approved lab trust design and is discarded at teardown.

**Recommend Android-first, subject to CTO/Security and rig availability.** Android #82 produced a debug APK, real unit and lint results for the permission shell. It gives a concrete entry point for OS consent, service lifecycle and permission revocation. A working engine, device environment and route measurement remain necessary. Desktop-first offers observable Linux networking and a reducer tested by GCC and Clang. It requires a privileged service, authenticated IPC and Qt integration. Prefer Desktop if a supported existing Linux rig and reviewed helper can meet the gates sooner. Identify the actual OS and network transitions tested. An emulated handover cannot establish physical Wi-Fi/cellular behavior. iOS requires separate Apple capabilities, signing, Xcode, a packet provider and device evidence. [Android job](https://github.com/Dimash313/Wexum/actions/runs/45005264504/job/137155346252) · [Desktop job](https://github.com/Dimash313/Wexum/actions/runs/45001872411/job/137144976935) · [Apple gates](https://github.com/Dimash313/Wexum/blob/76a9dc3b2cc36b7e9c19d7a591e53fc17af2bb47/apps/vpn/ios/Docs/APPLE_GATES.md)

**Fixture decision.** Obtain separate CTO/Security permission before enabling a lab-only synthetic subscription authority. Use authenticated server-only access, an isolated environment and audience, no public client route and no path into production provider ingestion. Test denial, change and revoke, then destroy the fixture. It provides no production billing evidence. Stage 3 can use an approved enrollment-only decision. That decision cannot authorize a tunnel before stage 4.
