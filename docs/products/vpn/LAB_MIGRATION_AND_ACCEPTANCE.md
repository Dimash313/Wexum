# First isolated WexumVPN connection

**Proposed engineering and acceptance specifications · NOT RUN.** One synthetic native client must exchange controlled traffic through an authenticated Gateway. Acceptance requires reproducible evidence of approved DNS, IPv4 and IPv6 behavior. A successful build, handshake, OS icon or offline classification alone cannot satisfy this gate. [Decision register](ADR-control-data-plane-trust.md) · [Dependency graph](COMPONENTS.md) · [Failure matrix](FAILURE_AND_PRIVACY_MATRIX.md)

## Laboratory and first client

Use disposable local hosts or existing isolated equipment. Separate client underlay, Gateway egress, control/management and observers. Provide internal DNS and controlled IPv4/IPv6 endpoints. Restrict egress to the laboratory. Calibrate an independent forbidden-path observer by showing it can see a synthetic marker in an intentional baseline run. Exclude production, real users or keys, payment data, public IP-check services, paid servers and new external services. Any future ephemeral test material requires the approved lab trust design and is discarded at teardown.

**Recommend Android-first, subject to CTO/Security and rig availability.** Android #82 produced a debug APK, real unit and lint results for the permission shell. It gives a concrete entry point for OS consent, service lifecycle and permission revocation. A working engine, device environment and route measurement remain necessary. Desktop-first offers observable Linux networking and a reducer tested by GCC and Clang. Qt6 compilation has since been demonstrated. Runtime validation still requires a privileged service, authenticated IPC and OS observation. Prefer Desktop if a supported existing Linux rig and reviewed helper can meet the gates sooner. Identify the actual OS and network transitions tested. An emulated handover cannot establish physical Wi-Fi/cellular behavior. iOS requires separate Apple capabilities, signing, Xcode, a packet provider and device evidence. [Android job](https://github.com/Dimash313/Wexum/actions/runs/45005264504/job/137155346252) · [Desktop job](https://github.com/Dimash313/Wexum/actions/runs/45086967946/job/137407700677) · [Apple gates](https://github.com/Dimash313/Wexum/blob/76a9dc3b2cc36b7e9c19d7a591e53fc17af2bb47/apps/vpn/ios/Docs/APPLE_GATES.md)

**Fixture decision.** Obtain separate CTO/Security permission before enabling a lab-only synthetic subscription authority. Use authenticated server-only access, an isolated environment and audience, no public client route and no path into production provider ingestion. Test denial, change and revoke, then destroy the fixture. It provides no production billing evidence. Stage 3 can use an approved enrollment-only decision. That decision cannot authorize a tunnel before stage 4.

## Packet-stop measurement contract for LAB-NEG-12 and LAB-NEG-17

**PROPOSED · NOT RUN.** QA #10 owns two independent-of-Gateway observation points (inputs and outputs on both traffic directions), an isolated marker source/sink and a control path to check instrument liveness. For each run pin the source/checkout SHA, build digests, OS, engine, topology, route/DNS policy, selected R08 profile, approved parameter values, clock sources/error, boot/generation, epoch, starting revision and initial outbox/watermark. Record observer identities and exact injection boundaries. Use run-scoped synthetic tenants, devices, permit references and marker sequences only. Run A and B on fresh equivalent fixtures; B requires separate authorization for the laboratory experiment.

1. Establish one authenticated session. Send distinguishable marker trains for each supported direction/path at a recorded bounded spacing. Baseline must demonstrate arriving ingress and matching egress and detect a deliberate forwarded marker at each sensor. Keep probes running during the fault and after the calculated deadline. Observe route and forbidden-path controls independently for DNS/IPv4/IPv6 claims.
2. Record authority order, last accepted challenge send/response, pre-issued expiry (B), partition injection, detection, stop decision, local actuation, last observed egress and receipt arrival as separate intervals. Include timebase offsets, resolution, timestamp uncertainty, maximum scheduling/marker gap, loss counters and buffering. The marker source must continue to reach the corresponding ingress. A dead source or capture drop cannot establish cutoff.
3. Use a separate live synthetic positive-control flow at each collector throughout. Calibrate with a known forwarding interval and a known stop on the same topology before and after the trial. Check marker counts/sequences, late queued packets and both directions. Extend observation past the deadline through the approved queue-drain and observation window. Report last forwarded marker and first sustained interval of missing egress with continuing ingress. A finite sampled trace supports only the tested configuration, traffic classes, interval and resolution.
4. Evaluate conservatively using the latest plausible stop and earliest plausible trigger. If the stop interval straddles the bound, or the measuring resolution cannot discriminate it, mark BLOCKED / NOT VERIFIED. A definite marker beyond the approved bound is FAIL, even when the UI says “disconnected.” A local `enforced` receipt plus matching independent evidence permits `confirmed_stopped` for that run. Missing authenticated evidence leaves the phase unknown. Keep post-recovery traffic on a new run/session distinguishable from stale traffic.

**Shared oracle and artifacts.** PASS requires every case-specific invariant, positive/negative control and mandatory artifact on the same build and boot history. FAIL records any proven safety violation or an instrument accepting a deliberately invalid evidence bundle. BLOCKED records missing owners/approved bounds, actuator, trustworthy clock, valid calibration, observer or verifiable artifact. Never infer PASS from a missing signal. Preserve a redacted manifest, authority/intent history and outbox/receipt digests, event-time brackets, slot counts, peer/boot and applied floors, synthetic path counters and independent observer attestations. Keep raw lab traces restricted. QA owns the manifest, each designated engineer owns the indicated instrumentation. Audit #78 checks provenance and repeats controls later.

### LAB-NEG-17B · Control partition with finite pre-authorized lease

Owners: #3 issuer, Runtime, Ops #8 and QA #10. With the same proved synthetic route, register a distinct B fixture. Record original authenticated online anchor, immutable expiry, tenant/device/session/peer/boot/generation and revision. Select a feasible observation window before and after expiry. 1. Partition Control while continuing ingress/egress probes. Repeat with loss just after lease issue and near expiry. Detect the partition by the agreed detection bound; freeze the original lease. Keep full data reachability while Control is offline.
2. Attempt new admission, lease extension, transport rekey presented as renewal, and cached reconnect. Reject every operation that would introduce new rights or move expiry. A lease valid on one already-active session cannot authorize another device, session, boot or peer.
3. Commit revoke R during partition. Delay it until after the deadline in one trial. **Rollback order.** First freeze issuance, new commits granting access and all positive refreshes. Continue restrictive commits, outbox delivery and emergency isolation. Inventory mixed generations, outstanding sessions, key profiles and minimum reader revisions. Close affected gates and independently verify cutoff (or keep a proven external fence in place) before releasing capacity. Persist tombstones, consumed permits, key invalidations, replay mappings and per-peer contiguous watermarks outside the rollback image.

Deploy readers that can enforce the highest required deny semantics before enabling writers for explicitly acknowledged peer/boot generations. An older client may list/revoke legacy device records when authorized; an unbound old device needs fresh proof. Older clients cannot claim verified state from an unsupported reader. A mixed-generation fleet never translates an incompatible permit or reuses an old registration. Refuse a downgrade that cannot read the current deny floor, even when that makes the lab unavailable.

To recover, verify the trusted checkpoint and complete journal tail against an independent latest floor. Restore **restrictions first**, reconcile each peer, require new enrollment/authority where needed, and exercise a previously revoked fixture as a negative control before opening a fresh eligible admission. Emergency signer compromise retires the key and every affected grant; restart issuance only under a freshly trusted profile after affected peers are fenced. A backup image or rollback action never grants entitlement.
